1. 项目概览

Game Recommender 是一款面向 PC 游戏玩家的 Chrome 扩展，核心价值在于把「下载站浏览」与「Steam 评分决策」打通：在 XDGame、咸鱼单机、Gamer520、3DM、游侠网、游民星空等下载站列表中直接显示 Steam 好评率徽章，在详情页注入 Steam 语言支持 / 标签 / 评测信息，在 Steam 页面反向检索各下载站的对应资源，并通过学习用户的浏览与下载行为预测其下载某款游戏的概率。

📌 关键事实（代码核实）

  • Manifest 版本：V3（后台为 module 类型 Service Worker）
  • 权限最小化：仅 storage + alarms，host_permissions 为 <all_urls>
  • 脚本规模：约 60 个 JS 文件，全部经典/模块脚本顺序加载
  • 测试：228 项单元/集成测试，node tests/run-tests.js 全绿
  • 数据层：OPFS 分文件存储，突破 5MB 配额，不可用时降级 storage.local

🎯 适用人群

  • 常逛国内单机游戏下载站、担心「坑货」的玩家
  • 希望在下载前快速判断 Steam 口碑与中文支持的用户
  • 希望「一个页面搞定：看资源 → 查口碑 → 比价 → 一键领取限免」的轻度玩家
  • 对「行为学习推荐」感兴趣、愿意接入本地 LLM 的进阶用户

3. 系统架构设计（架构图）

运行时存在三条协作主线：内容脚本（注入下载站/Steam 页面）与后台 Service Worker 通过 Chrome Messaging 通信；后台统一对外请求 Steam / 限免平台 API 并写入 OPFS 数据层；扩展页面（popup/options/dashboard/freegames）亦经消息机制读写同一后台。

🔑 三条关键设计决策

  • 两波好评率流程：列表页第一波仅查缓存（零网络，徽章即时显示），未命中由后台从 Steam 拉取、每批完成后增量推回页面。该设计规避了 MV3 Service Worker 空闲 30 秒休眠导致批量结果丢失的问题。
  • SW 保活：后台批量循环每 10 秒调用 chrome.runtime.getPlatformInfo() 重置空闲计时器，并内置失败重试队列与 API 异常降速（间隔 1.5s→5s，连续异常暂停 30s）。
  • 模块化 Steam 缓存（v3.3.7）：缓存条目按 {modules:{meta,rating,detail,spy}} 分组，每个模块独立 TTL、独立刷新。好评率过期只刷新好评率，详情页/补充数据不受影响，从根本上消除「缓存结构调整即全量失效」的痛点。

4. 核心功能特点

以下功能均经源码核实，按用户价值排序：

① 浏览行为追踪与智能推荐

追踪用户在下载站（XDGame/咸鱼单机/Gamer520/3DM/游侠/游民星空）的浏览与下载行为。v3.2.8 重构为 appId 维度的个性化概率预测：综合「该游戏自身的行为信号 + Steam 标签与用户偏好匹配 + 好评率(70%) + 中文支持(30%)」，不同游戏得不同分值，列表页以 🎯 徽章呈现并高亮高推荐项。支持接入 Ollama 本地模型 / OpenAI 兼容接口作为 LLM 评分。

② Steam 信息集成

详情页自动注入仿 Steam 信息浮窗：总体评价、简体中文评价、SteamSpy 评分三重体系；中文支持情况（简/繁体、音频、字幕）；热门用户标签、开发商、发行日、最近更新、简体中文评测摘要。从商店页 HTML 与多 API 聚合而成。

③ Steam 好评率徽章 + 过滤

列表页每个游戏标题前显示三段式徽章：近 30 天好评率 → 全部好评率（分级着色、可点击跳转）→ 最近更新日期。支持按阈值（0%–95%，步进 5%）过滤低评分游戏，过滤后自动重排不留空。0 评测游戏显示灰色 AppID，未匹配显示「未找到」。

④ 虚拟机版过滤

隐藏标题含「虚拟机板/虚拟机」的游戏（关键词可自定义），从 DOM 移除整个栅格列容器避免留空。该过滤在请求 Steam 数据之前执行，同时节省 API 调用。

⑤ 下载站资源检索

在 Steam 详情页自动检索 XDGame/咸鱼单机/Gamer520 的对应资源（范围可勾选），显示更新日期、版本、大小、网盘链接（自动拼提取码）。采用跨语言标题匹配算法 + 自适应检索（删词组合 + 噪声词自动学习）。

⑥ 下载历史记录

详情页自动记录每次下载行为，显示上次下载时间、站点、次数，提供快捷跳转。以 appId 维度写入下载站网址缓存。

⑦ 限免游戏监控

每日自动刷新 Epic / GOG / GamerPower 的限免游戏，扩展图标角标显示未领取数量，支持一键领取跳转。基于 alarms 定时，启动即刷新。

⑧ 数据管理 + 规则管理

备份/恢复（JSON，模块勾选）、设置自动保存（800ms 防抖）、游戏缓存管理页（多条件检索/分页/删除/手动更新/清理过期/修复异常名）。v3.0 规则编辑器支持查看/编辑/导入导出/恢复内置，后台二次校验纯数据白名单防注入。

⑨ 统一浮窗体系（v3.1）

所有浮窗（状态/诊断、Steam 信息、下载站资源、下载历史）经 GR.float 统一管理：分区定位、防重叠堆叠（ResizeObserver 自动重排）、统一折叠/关闭。

⑩ 自适应检索（v3.1.2）

标题检索失败时自动尝试删词组合（尾/头逐词删除 + 已学噪声词清洗），成功后自动学习被跳过的噪声词（计数 ≥3 次生效，防误学副标题）。检索规则随使用自动改进，新站点修饰词无需手动维护。

6. 优点与不足分析

✅ 优点

维度具体表现
架构清晰后台严格分层（core→storage→业务→handlers→入口），单向依赖、无循环；内容脚本按功能横切为 core/list/detail/tracking。README 明确给出依赖方向约束。
缓存体系成熟三层缓存（注册表 / 名称索引 / 网址缓存）+ 模块化子缓存（meta/rating/detail/spy 独立 TTL）。跨站共享好评率、按自身 TTL 部分刷新、旧结构自动迁移、失败固化自动重试、0 评测冷却。
MV3 工程实践扎实SW 保活、批处理落盘、flush 安全化（配额超限不中断主流程）、异步消息正确返回 true、AJAX 页 MutationObserver 等待。
安全设计到位出站请求 SSRF 校验；动态 HTML 全部转义；规则导入纯数据白名单 + 拒绝函数注入 + 规模上限；百度网盘链接拼接前域名校验。
健壮性高大量边界防御：畸形 href 跳过、content 脚本 SW 冷启动重试、限流退避、网络失败重试、缓存缺失自动补写注册表、名称自愈。
质量保障228 项自动化测试全通过，覆盖纯函数（标题解析、评分）、安全（SSRF/ND-JSON/TDZ）、缓存清理、内容脚本模拟；变更日志详细到每个修复的根因。
可扩展性好新增下载站只需在 adapters/sites/ 增加一条规则（数据驱动），无需改代码；规则支持用户导入覆盖与导出分享。
数据层先进OPFS 分文件 + ND-JSON 追加写入，突破 storage.local 5MB 配额并有降级路径与旧数据迁移。

⚠️ 不足与风险

问题影响证据（代码位置）
中等 双重范式 + 全局命名空间后台用 ES Module，内容脚本用 window.__GR__ 全局对象共享，隐式耦合、无类型安全，重构易漏。content/tracker.js 取 GR.common/debug/builder/list/detail；content/core/floats.js 等以 IIFE 挂全局
中等 常量重复定义noisePattern 正则同时出现在 title-parser.js 与 detail/detail-page.js；escapeHtml/escapeAttr 在 shared/escape.js 与 content/core/common.js 各有一份。改一处易漏另一处。steam/title-parser.js:11 与 detail/detail-page.js:55；shared/escape.js 与 content/core/common.js:20
中等 Steam 页面解析依赖正则中文支持表、用户标签、详情页元信息均用正则抓取商店页 HTML，站点改版即失效，需人工跟进（历史变更日志已多次因此修复）。steam/api.js 的 parseChineseLanguageSupport/parseUserTags；sites/search.js 的 extractDetailMeta
较高 无类型系统纯 JS，约 60 文件、数千行；历史上出现 TDZ 导致整个后台加载失败（v1.11.1）、steam_appid 字段不兼容导致详情页 100% 失败（v3.3.4）等运行时坑，靠测试/审阅兜底。README v1.11.1、v3.3.4 变更记录；core/constants.js 用字符串字面量规避 TDZ
中等 站点选择器硬编码各下载站的容器/标题选择器写死在规则文件，页面结构变化需手动更新规则。adapters/sites/*.js 的 listItem.containers 等
较低 列表扫描上限 500 链接通用列表页判断扫描至多 500 个 a 标签，超大页面可能漏判或开销偏高。content/adapters/builder.js:79
较低 无浏览器端 E2E 测试测试仅覆盖纯函数/单元/接口模拟，缺乏真实页面注入与交互的端到端验证。tests/ 均为 *.mjs 逻辑测试
较低 无 i18nUI 文案与注释硬编码中文，国际化（英文用户）需整体改造。全部前端文件
总体判断：优点显著且经过工程实践验证（测试全绿、缓存/安全/健壮性均到位），不足主要集中在「无类型 + 全局耦合 + 正则脆弱」三项，均为可治理的技术债，不构成阻断性问题。

7. 中文使用指南

1

2
打开 Chrome，访问 chrome://extensions/。
3
右上角开启「开发者模式」（Developer mode）。

点击「加载已解压的扩展程序」（Load unpacked），选择项目根目录文件夹。

  1. 「数据驱动 + 规则文件」解耦：站点适配全部下沉为 adapters/sites/*.js 的纯数据规则，新增站点零代码入侵；用户还能在设置页覆盖/分享规则。这是高可维护性的关键。
  2. 「缓存优先 + 增量推送 + 自愈」三角模型：用缓存命中即时显示、后台异步补拉、失败/0评测自动重试与冷却，既保证体验又规避 MV3 休眠丢失。该模型跨越列表页、详情页、缓存管理页三处一致实现，工程一致性高。

可维护性上的主要隐忧

  • 内容脚本的全局命名空间：window.__GR__ 把模块耦合在运行期全局对象上，IDE 无法静态追踪依赖，重构时极易遗漏。建议逐步迁移为内容脚本 ES Module（MV3 已支持 "js" 以模块方式加载内容脚本）。
  • 重复常量：noisePattern 与转义函数在两处重复，是最典型的「改一处漏一处」陷阱，应抽到 shared/ 统一引用。
