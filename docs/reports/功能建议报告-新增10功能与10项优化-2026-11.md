## 二、新增功能建议（10 项）

### N1 好评率走势迷你图（sparkline）

- **是什么**：评分缓存写入时追加 `{ts, rate}` 到条目级 history 数组（有界 30 点），
  详情浮窗与 dashboard 以 SVG polyline 渲染走势；数据纯积累型，**零新增请求**。
- **原因**：当前只有"总体 vs 近 30 天"两点，看不出口碑是崩坏还是回升——而走势恰是
  "该不该下"决策的关键信号；且坏口碑修复（厂商救火）用户完全无感。
- **原理**：rating 缓存每次重取成功即追加点（冷却语义保证点距 ≥5min/1h）；history
  上限 30 点超限淘汰最旧（`evictOldestByTs` 单源已有）；SVG 60×20 无依赖绘制；
  dashboard 侧 dash-* 模块化基建已就绪（R9 B3 雷达图先例）。
- **成本/优先级**：3h · P1 · 验收 = 浮窗+dashboard 双挂点渲染、30 点上限断言、空 history 降级隐藏。

### N2 系统兼容徽章（Win/Mac/Linux + Steam Deck 验证态）

- **非 PC 平台专项（v14.10.0）的延长线**：MC 分已有，缺平台兼容信号。
- **原因**：mac/linux 用户当前零信号；Steam Deck 玩家无法预判可玩性；
  `platforms` 字段就在 appdetails `filters=basic` 响应里（**零额外请求**）。
- **原理**：basic 响应 `platforms{windows,mac,linux}` 三布尔 → 徽章图标行（🐧/🍎/🪟）；
  Deck 验证类别在商店页 HTML（回退解析管线已在——`home_deck_compatible` 区域类名），
  作为可选增强项挂在同一解析器（复用三形态解析器骨架，P3）。
- **成本/优先级**：2h（platforms）+3h（Deck 解析）· P2 · 验收 = 三平台徽章渲染 + 无信号降级隐藏。

### N3 AppID 手动绑定（下架/搜不到游戏的用户兜底）

- **是什么**：候选浮窗（未找到路径）新增"手动输入 AppID 绑定"入口——粘贴 Steam 商店
  URL 或纯数字 appId → 拉详情确认存在 → 写入纠正映射（与候选选择同语义，优先于一切索引）。
- **原因**：实测 storesearch **搜不到已下架游戏**（v14.6.0 调研 The Culling 实证），
  目录索引 miss 时用户**没有任何手动兜底**；用户从 Steam 网页找到游戏后 URL 里就有 appId。
- **原理**：候选面板加输入框 + appdetails 确认（`success` 校验防错绑）+ `saveCorrection`
  复用（纠正库语义已闭环：优先于索引、清负缓存、粘性化）；提交侧校验对齐
  `APP_ID_RE`（1-10 位数字）。油猴版同 UI（油猴 candidates 已有该面板，加一输入框）。
- **成本/优先级**：2h（扩展）+1h（油猴）· P1 · 验收 = URL/纯数字双格式、无效 appId 拒绝、绑定后负缓存清除。

### N4 "重试全部失败项"批量按钮

- **是什么**：列表页失败徽章（未找到/失败固化）≥2 时，面板出现"🔄 重试全部失败项"，
  串行走既有 RETRY_GAME_LOOKUP 窄化 action，**有界**（≤20 项/次 + 单飞行守卫）。
- **原因**：网络恢复后用户需逐个点击失败徽章（20 次点击）；自愈优先纪律允许"总量
  有界的自动重试"，批量的手动触发是同纪律的用户侧形态（用户发起 = 有明确意图）。
- **原理**：失败徽章已有 dataset.grAppId/gameName 数据桥（点击重查管线复用）；
  面板按钮遍历收集 → 逐项串行（限速槽内建）→ 逐项更新徽章（就绪快路径语义）。
- **成本/优先级**：2h · P2 · 验收 = 上限 20 断言、单飞行防重入、逐项徽章更新推送。

### N5 人工纠正映射导出/导入

- **是什么**：纠正知识库（manualMappings）独立导出为 JSON 信封文件 / 从文件导入，
  独立于全量备份（现仅随备份混出，无独立入口）。
- **原因**：纠正映射是用户逐个手动确认的劳动成果（换机/重装即失）；v10.9.2 以来
  纠正库优先于一切自动索引——它是匹配质量的人肉防线，可迁移性=安全感。
- **原理**：导出 = STORAGE_MODULES 读取 + `{grEnvelope:1, kind:'manualMappings',
version, entries}` 信封（**对齐 R9 B5 过滤预设信封先例**）；导入 = 逐条校验
  （APP_ID_RE + 名称长度）+ upsert + 上限 CAP；不碰"规则市场"红线（本地文件，非分发平台）。
- **成本/优先级**：3h · P1 · 验收 = 导出→清空→导入还原 roundtrip 测试、非法条目拒绝计数。

### N6 站内通知中心

- **是什么**：扩展工具栏弹层（或 hub 页签）聚合限免/折扣/周报/规则失效告警的历史
  记录（环形 50 条）+ 未读计数 badge；系统通知照旧，站内可追溯。
- **原因**：chrome.notifications 即焚——用户错过就没了，且历史不可查；"上周那个
  限免叫什么"无解；规则失效告警（SITE_ADAPTER_ALERT）现在只进日志。
- **原理**：现有 4 个通知触发点各加一行"落库"（环形 50，STORAGE_CAPS 模式）；
  弹层复用 popup 面板骨架（popup 已 491→287 拆分后的面板化结构）；未读数 =
  `chrome.action.setBadgeText`（现有权限）。
- **成本/优先级**：4h · P2 · 验收 = 4 类通知落库断言 + 50 条环形淘汰 + 未读计数清零链。

### N7 限免日历 iCal 导出

- **是什么**：限免页/月历加"导出 .ics"按钮——把当前限免（含进行中/ upcoming）
  生成 VCALENDAR 文件下载，可订阅进系统日历。
- **原因**：限免是**时间敏感**收益（错过=损失），而用户不会天天打开扩展；日历推送
  是用户已有习惯的提醒渠道，零维护成本。
- **原理**：freegames 数据已含起止时间戳（R9 B2 月历已消费）；ics 生成 = 纯函数
  （VEVENT DTSTART/DTEND/UID 确定性生成，单测友好）；Blob 下载零权限。
- **成本/优先级**：2h · P2 · 验收 = ics 格式 golden 断言（起止/时区 UTC 化）+ 空数据降级。

### N8 油猴版自动更新链

- **是什么**：脚本头加 `@updateURL/@downloadURL`（GitHub raw 主源 + jsDelivr 备源
  注释行），Tampermonkey 自动检查更新。
- **原因**：油猴版无更新机制——用户停在旧版（词表/管线修复到不了），版本号纪律
  的"区分内容是否更新"在油猴侧断链。
- **原理**：TM 原生机制零代码；**双源**应对 GFW（raw.githubusercontent 拉取失败是
  实测常态——AppListIndex dump 拉取失败同因）；发布流程补一步"同步 userscript 版本头"。
- **成本/优先级**：0.5h · P1 · 验收 = TM 更新探测成功 + 发版清单（AGENTS 发布流程）补条目。

### N9 内置站独立开关

- **是什么**：设置页新增内置站点启用开关组（xdgame/xianyudanji/gamer520/3dm/ali213/
  gamersky 逐站 on/off），关闭 = 不注入不查评分。
- **原因**：隐私最小化诉求（"我不用 3dm，为什么要注入"）；性能（无关站零开销——
  tracker boot 已按规则早退，但静态注入本身发生在页面）；自定义站本就按规则注册，
  内置站反而是唯一不可关的。
- **原理**：`settings.disabledSites[]` + tracker boot 入口一行判断（已有早退骨架）；
  manifest content_scripts 静态注入无法撤回（MV3 限制）→ 关闭站靠 boot 早退 +
  fetch 拦截为零请求，页面注入开销保留（诚实记录为已知限制）。
- **成本/优先级**：2h · P3 · 验收 = 关闭站零消息/零请求断言 + settings-sync 同步（OPTIONS_ALLOWLIST 评估）。

### N10 浮窗"系列作品"导航行

- **是什么**：浮窗新增"系列作品"行——展示名称索引中同系列条目（前作/续作/DLC 本体），
  点击直达对应 Steam 页/站内搜索。
- **原因**：在续作/前作间导航是高频动作（用户从"XX2"页面找"XX1"）——跨站对比表
  （B7）解决跨站，没解决跨**作**；数据已在本地（nameIndex 积累的 cnName→appId），
  零请求零成本增量功能。
- **原理**：系列识别 = 版本对照词表（versionSuffixes 8 对）+ 共同前缀 token 聚合
  （coreTokensOf 前缀重合 + 序号差异）；nameIndex 全量扫（有界 600 条，内存态遍历
  零 IO）；点击 = 打开 Steam 页或站内 searchUrl 模板（规则已含）。
- **成本/优先级**：3h · P3 · 验收 = 系列聚合纯函数单测（versionPairs 用例）+ 零命中降级隐藏。

## 三、现有设计优化（10 项）

### O1 DLC 解析与详情获取共享 appdetails 往返 ✅已核实

- **现状**（orchestrator-shared.js:87-96 + orchestrator-detail.js）：元素直取路径
  Phase 0 `resolveDlcToBase` 轻量查 appdetails basic → 后续 `fetchSteamFullDetailsByAppId`
  **再查一次完整详情**——同 appId 两次商店页往返。
- **原因**：直取命中是列表页主路径（gamer520 等站封面全带 appId）；每次省 1 请求 =
  批量场景省 N 请求，直接降低限速排队与熔断压力。
- **原理**：`resolveDlcToBase` 改返回 `{appId, detail}`（轻量 basic 响应已含 name/type/
  platforms），后续完整获取只补 reviews/spy 段——**与油猴版 rateGame(hint.details)
  的 hint 模式同形**（油猴先例已验证该形态可行）。
- **成本/优先级**：2h · P1 · 验收 = 直取路径 appdetails 调用计数 2→1 断言（test-orchestrator 补锚点）。

### O2 目录层受控模糊匹配落地（v14.6.0 遗留立项）

- **现状**：目录索引仅归一化精确 + deSpace 空格变体二级索引；模糊匹配"阈值校准待后续"。
- **原因**：下架游戏 storesearch 无路可走（The Culling 实证）——目录是唯一覆盖源；
  实测存在"精确 miss 而模糊明显 hit"样本（副标题/标点差异）。
- **原理**：受控 = 三重护栏——①社区校准阈值（Dice ≥0.65，Steam-App-ID-Finder 经验值）
  ②候选必须通过 nameMatchesSearch（相关性不因模糊放水）③lookupTiered tier 计数
  指标门（fuzzy.hit 独立计数已有，回放门禁防退化）。
- **成本/优先级**：3h · P2 · 验收 = 错题库回放不回归 + 基准 Top10 不回归 + fuzzy.hit 指标卡。

### O3 未找到徽章动态负缓存剩余时间 ✅已核实

- **现状**（badges/core.js:55）：title 静态文案"负缓存 2h 后自动重查"——而分级退避
  （v14.7 B4）实际是 15min→1h→2h 三档，**文案与实际行为不一致**（首档 miss 用户
  看到的 2h 是错的）。
- **原因**：v14.13 用户"一直卡在等待检测"类困惑的同源——期望管理失真；渲染时按
  missCount 算真实剩余即可。
- **原理**：nameIndex 条目已含 lastSearched+missCount → `negativeTtlFor(missCount) -
(now-lastSearched)` 剩余分钟渲染进 title；渲染函数已有 settings 参数管道。
- **成本/优先级**：1h · P2 · 验收 = 三档剩余时间渲染断言（sim 桩 missCount 1/2/3）。

### O4 CI 接入 E2E MOCK（暂缓理由失效复核）

- **现状**：ci.yml = lint + typecheck + 棘轮 + vitest 分片×2，**无 E2E**；暂缓理由
  （重构报告 §3.4）是"E2E 3 连绿在满载机不可复现"——那是**本机** FaceFusion 负载。
- **原因**：GitHub Actions runner（4 核恒定）无该负载；E2E_MOCK=1 已完全离线
  （fixtures 87 个 + MOCK_RE 域拦截，网络抖动为零）。暂缓理由随环境变化**已失效**，
  复核推翻——E2E 是历史确定性回归（欢迎页/详情三连/scroll）的唯一门禁，不上 CI
  等于每次发版裸奔。
- **原理**：ci.yml 增 e2e job（`E2E_MOCK=1 npm run e2e` + playwright chromium install）；
  runner 上先跑一次全绿基线确认，再设必过；失败重跑 1 次（抖动余量）。
- **成本/优先级**：1h + 观察期 · P1 · 验收 = CI 三连绿 + 本地 MOCK 51/51 同口径。

### O5 徽章批量插入 DocumentFragment

- **现状**：processItem 循环逐项 `insertBefore` 挂徽章——60 项首屏 ×2 徽章 ≈120 次
  独立 DOM 写（各引发重排）。
- **原因**：大列表页（maxScanLinks 500）首屏可感知卡顿；批写是零风险纯性能优化。
- **原理**：每波次徽章先挂到 DocumentFragment，波尾一次性 `insertBefore(fragment, …)`；
  注意保持"就绪快路径同步应用"语义——**逐项就绪仍逐项显示**（串行队列下每项完成即挂，
  Fragment 仅用于同一项的 2 枚徽章组合插入）。
- **成本/优先级**：1h · P3 · 验收 = sim 徽章断言全绿 + 大列表（500 项）插入耗时对比记录。

### O6 规则包导入侧 mismatch 回放门（R2 遗留立项）

- **现状**：词表覆盖（retrievalVocab）随规则包导入即时热更（v14.7 B12），导入侧无
  匹配质量门；PROTECTIVE_TITLES 防护标题表是**运行时**防线（v14.7 B2），mismatch
  回放器只在 CI/命令行（mismatch-replay.mjs）。
- **原因**：词表是检索大脑——坏包（噪声词误删正主词）会静默劣化全站匹配，且用户
  无感知（错题库回放只在开发侧跑）。
- **原理**：导入 handler 进程内跑轻量回放子集（fixtures 5 锚点 + PROTECTIVE_TITLES 8 条，
  复用 mismatch-replay 运行器核心纯函数）——不达标整包拒绝（对齐 v14.7 B12"显式非法
  整包拒绝"语义的延伸：合法但**劣化**也拒）。
- **成本/优先级**：3h · P2 · 验收 = 好包过/坏包拒（构造噪声词污染包用例）双断言。

### O7 一键诊断包导出

- **现状**：EXPORT_LOGS 只含运行日志；用户报障需多轮往返（v10.9.2 教训："用户侧环境
  不可远程推断"——显性化是既定方向，但收集动作仍要用户手动拼）。
- **原因**：报障往返成本高（版本/设置/失败原因/缓存状态分散多处）；一键包让 issue
  一来一回闭环。
- **原理**：聚合 导出设置（**stripSecrets 单源已有**——v14.11 B3）+ 运行指标
  （GET_RUNTIME_METRICS）+ API 状态（GET_API_STATUS 含 failAttribution 环形缓冲）+
  最近日志 → 单 JSON 下载；options 帮助区加按钮（EXPORT_LOGS 骨架复用）。
- **成本/优先级**：2h · P1 · 验收 = 诊断包含四段且密钥字段全脱敏断言。

### O8 油猴-扩展纯函数双侧 golden 对齐测试

- **现状**：油猴词表已有防漂移门禁（22 例），但纯函数（nameMatchesSearch/
  matchCandidateScore/coreTokensOf 等）只有油猴侧锚点用例——扩展侧改纯函数而油猴
  快照未跟，词表门禁不红（行为漂移静默）。
- **原因**：油猴管线的行为正确性=扩展快照的正确性；错题库锚点（寂静岭/BO7/生化危机4）
  应该在**两侧跑出同一结论**。
- **原理**：错题库 fixtures 单源（tests/fixtures/mismatch-samples.json）→ 同一用例集
  分别喂扩展模块与油猴沙箱（vm 装载已有）→ 双侧输出深度相等断言；扩展侧新增用例
  自动进入油猴门禁。
- **成本/优先级**：2h · P2 · 验收 = 双侧 5 锚点全等断言 + 扩展侧改函数油猴门禁变红演练。

### O9 E2E MOCK_RE 覆盖自动审计

- **现状**：MOCK_RE 域拦截清单靠人工维护——**历史上漏了三次**（v14.8.0 教训④：
  appreviews/商店页回退/Bing 三处漏拦致 MOCK 漂移真网络，回放结果随外网漂）。
- **原因**：新增出站端点忘加 MOCK_RE = E2E 假绿（真网络模式下才暴露），这是已三犯
  的结构坑；域清单可从代码静态推导。
- **原理**：test-integrity 新断言——扫描 background/content 的出站 URL 字面量域集合
  ⊆ MOCK_RE 域清单 ∪ 显式豁免表（ENDPOINTS 单源可枚举，油猴 @connect 同表核对）；
  新端点接入即红，逼同步。
- **成本/优先级**：2h · P1 · 验收 = 现有端点全过 + 构造新端点漏登记用例变红演练。

### O10 油猴列表扫描增量标记

- **现状**（userscript runListPage）：MutationObserver 每轮 rescan 全页重扫所有链接
  （fallbackLinks 全页 a[href] 遍历 ×20 轮上限）——大页面 O(20×N) 无谓扫描。
- **原因**：油猴版跑在用户页面上下文，重复全页扫是纯浪费（已徽章化项不可再处理）。
- **原理**：WeakSet 已处理 link 标记（GC 友好，节点移除自动清）+ 容器级增量
  （MutationObserver records 只扫新增节点——扩展 findItemsInContainer 同模式先例）。
- **成本/优先级**：1h · P3 · 验收 = 模拟懒加载 20 轮扫描节点访问计数下降断言。
