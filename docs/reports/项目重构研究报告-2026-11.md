## 三、当前债务地图（按性价比排序）

### 3.1 类型债（隐式 any 全家族 1669 处：main 878 / ui 347 / content 444）

**现状**：棘轮只数 TS7006（495），但全家族（TS7053/7017/7005 等）实测 1669。
报告 D P0-2 指出的"形态绕过"已部分兑现——写 `function f(x: any)` 可让计数
下降而债务未还。

**重构方案（增量推进，不做全量 TS）**：
1. 棘轮计数扩为隐式 any **全家族之和**，首跑基线一次性锁 1669（只降不升）
2. 按密度清偿：message-contract 规则表 `(m)=>` 形态（~60 处）用表驱动
   `RuleFactory` 类型一次清一个文件；data-store.js（22 处）补 OPFS 记录类型
3. `typescript` 锁精确版本（caret 漂移已实测造成基线浮动 ±3）
4. 预期收益：类型即文档 + 消费方自动补全 + 悬空字段编译期暴露

**成本**：每文件 0.5-2h；总 ~15h 可清至 <400。**优先级 P2**。

### 3.3 测试体系两处保真度缺口（报告 D P1-10）

- storage mock `get` 返回内部引用（真实 chrome.storage 是结构化克隆）——
  改 structuredClone 返回会让部分现测试暴露"就地改值未 set"的真实缺陷，
  **预期会红一批**，需连带修
- fetch mock 缺 `headers.get`/`clone`——fetchWithTimeout 重定向复检路径
  在 mock 下不可达

**优先级 P2**（mock 保真是所有并发/持久化测试可信度的地基）。

## 四、方法论沉淀（本轮十四版迭代实证）

1. **拆分必须有机器锚点先行**：B1 四阶段拆分的锚点门（294 用例）在两次
   重构事故（丢赋值/const 化）中 3 分钟定位——无锚点的等价重构不可接受
2. **单源化先证明"多份"真实存在**：报告"6 份防抖拷贝"实测仅 1 处——
   重构前逐份复核消费方
3. **单源落位防循环**：共享函数放依赖下游（isXdgameFallback 落 layout
   而非 xdgrid）
4. **测试桩保真度先行于重构**：FakeEl 缺 isConnected 导致语义升级即红——
   桩补齐是重构前置
5. **诊断直通**：Logger 不落 console 的 SW 环境，"生命周期日志 + 队列
   快照 action"是挂起类问题的唯一定位手段
