# 迭代路线图 · 第二轮 10 批次（2026-09-28 规划）

> 基线：v11.0.0（840 test · 10 批次第一轮已全量落地：熔断器/分域可达性/收藏折扣监控/
> 浮窗拖拽/设置搜索/标签聚合/洞察导出/Ollama json/理由上浮）。本轮**不限维度**，
> 在修完已知短板（分域熔断、content-sim 深度重写）之上，向三个新方向扩展：
> **MV3 新 API 面**（SidePanel）、**决策辅助**（发售追踪/跨站比价/最优来源）、
> **键盘与无障碍**。约束不变：零构建、明确不做清单照旧；每批独立 gate+发布。

## 批次1【稳】分域熔断 + 半开探测

目标：v11.0 的熔断器是全局一把闸——api 域（GetNewsForApp，大陆常不可达）挂掉会把
store 域（搜索/详情/评价，通常可达）的请求也一起熔断。改为**按域独立熔断 + 半开探测**。

- 熔断状态从全局改 per-domain（store/api 各自计数与开合；api 域 4s 探针即天然探针）
- **半开探测**：熔断到期后不放行全量请求，先放行 1 个探测请求，成功才闭合（防雪崩）
- 熔断事件进 runtimeLog + reason 字段（"熔断中(store)"），前端状态卡已有分域点灯
- 验收：模拟 api 域断网 → store 域搜索正常；探测成功后自动闭合（单测钉死）

## 批次2【稳】content-sim 状态机重写（E3 终版）

目标：负载敏感抖动的深度根治，移除 retry 2 缓解（它是绷带不是修复）。

- list-state 暴露**显式信号**：`waitForBatchIdle()`——批次队列排空 + 推送应用完毕
  的 Promise（内部计数器，非时间轮询）
- 测试改用信号等待替代 `waitForTimeout`；文件级 retry 2 移除
- 输出 yaml 回归记录进 CONTRIBUTING（抖动根因：消息推送与批次队列的时序竞争）
- 验收：全量并发下 20 连跑全绿、零 retry；CONTRIBUTING 已知问题节关闭

## 批次3【性】请求去重与消息背压

目标：并发场景下的重复请求与消息风暴（多标签页同时打开同一游戏）。

- **in-flight SEARCH_STEAM/GET_STEAM_BY_APPID 去重**：同参并发请求共享同一 Promise
  （现在每 tab 各自全链搜索，3 个 tab 同游戏 = 3 倍 Steam 请求）
- **TRACK_EVENT 批量合并**：内容侧 500ms 攒批一次发送（现在每个事件一条消息，
  大列表页滚动时消息风暴）
- 验收：metrics.msg.TRACK_EVENT 数量下降 ≥60%（同场景 A/B）；并发去重单测钉死

## 批次4【交】浮窗信息模块自定义

目标：浮窗信息密度已高，让用户自己决定"看什么、按什么顺序"。

- 设置项：浮窗信息区各块**显隐**（中文支持/用户标签/开发商/SteamSpy 面板/ITAD 行/
  收藏按钮/Steam250 行/更新徽章）
- **拖拽排序持久化**（复用 B5 拖拽机制，顺序按浮窗 id 存储与位置同键族）
- 验收：任意块可隐藏/调序，刷新后保持；默认全显示（不破坏现有用户）

## 批次5【交】候选列表键盘导航 + 无障碍

目标：候选匹配是核心交互路径，全程键盘可完成 + 读屏可用。

- 候选列表 ↑/↓ 导航 + Enter 选择 + Esc 关闭（焦点管理）
- 浮窗补 aria-label/role/tabindex；徽章 title 已有——补 focusable 顺序
- 验收：不开鼠标完成"打开浮窗 → 搜索 → 选候选 → 确认"全流程；axe 类检查零严重项

## 批次6【功】发售日追踪与提醒

目标：未发售游戏的"等发售"场景目前完全无覆盖。

- 解析游戏 releaseDate（未来日期）→ 浮窗显示**发售倒计时**徽章
- 收藏中的未发售游戏 → 发售日 alarm 到期通知（复用折扣监控的通知管线）
- dashboard 收藏区标记"未发售"分组
- 验收：收藏未来发售游戏 → 到日通知；倒计时随刷新更新

## 批次7【功】跨站收录对比 + 最优来源标记

目标：同一游戏多站收录时，用户手动逐站对比——应自动对比并给推荐。

- SEARCH_DOWNLOAD_SITES 结果聚合：各站版本号/大小/更新时间并排对比表（浮窗内
  折叠展开）
- **最优来源标记**：更新时间最新 + 完整度（全DLC/中文）打"⭐ 推荐"角标
- 验收：多站收录游戏自动标记；单站收录不显示对比（降噪）

## 批次8【易】列表工具栏：本地排序 + 过滤预设

目标：列表页现在只能"过滤"不能"排序"，且过滤条件每次重设。

- 浮窗/页面工具栏：按**好评率/更新日期/综合评分本地排序**（纯 DOM 重排，不发请求）
- **过滤预设**：当前过滤条件（开关+阈值）存为命名预设（如"只看95+中文"），一键切换
- 验收：千项列表排序 <300ms；预设跨刷新持久

## 批次9【先】MV3 SidePanel 仪表盘

目标：chrome.sidePanel（Chrome 114+）承载 dashboard 精简版——浏览站点时侧边常驻，
不再切 tab。

- SidePanel 页：当前页游戏信息 + 收藏列表 + 限免速览（dashboard 精简组件复用）
- 版本降级：Chrome < 114 隐藏入口（popup 加载时探测）
- 验收：侧边栏随当前 tab 联动显示对应游戏信息；旧 Chrome 无感

## 批次10【发】CWS 上架执行 + 周报 digest + 反馈入口

目标：把"准备完毕"变成"提交审核"，并给用户一个反馈与回顾通道。

- **CWS 提交**：STORE.md 资产终稿执行（需用户开发者账号；扩展侧全部就绪）
- **周报 digest**：每周一通知上周统计（浏览/下载/收藏/折扣节省），dashboard 周报卡
  （数据全在 trends + metrics，纯聚合）
- **浮窗反馈入口**：浮窗菜单加"反馈问题"→ GitHub Issues 模板预填（版本/页面/日志
  摘要，用户确认后才打开）
- 验收：提交流程走完；周报通知可关闭（设置键）
