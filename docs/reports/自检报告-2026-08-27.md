## 二、P1 严重问题（8 个，功能失效 / 数据破坏 / 可利用注入）

### P1-1 删除缓存条目不落盘，SW 重启后"复活"
- 位置：`background/handlers/cache-manager.js:221-227` + `background/storage/registry.js:127-136`
- `handleDeleteGameCacheEntry` 中 `delete registry[appId]` 只改内存（`getGameRegistry()` 返回活引用），随后 `flushRegistry()` 因 `registryDirty` 从未置位而直接 return——删除从未写盘。MV3 SW 空闲 30s 即被杀，删除的条目随即复活。
- 对照：同函数内 `deleteSteamCacheEntry`（steam-cache.js:306）显式置 dirty 并带注释说明这个坑，唯独 registry 漏了。
- 修复：删除后调用 `scheduleRegistryWrite()` 或直接置 `registryDirty = true`（一行）。

### P1-2 手动纠错映射永不保存（主路径缺 gameName）
- 位置：`content/detail/detail-page.js:458-463`（发送端）vs `background/core/message-contract.js:99-102`（契约 gameName 必填）
- 自动搜索失败 → 手动选择浮窗的回调只发 `{ action: 'SAVE_MANUAL_MAPPING', appId }`，闭包中明明有 `gameName` 却没带；消息在契约校验层即被拒（`invalid-message`），且 `.catch(() => {})` 吞掉错误，完全静默。
- 后果：用户手动选对的游戏，下次访问同一页面仍然错配。对比 `detail-page.js:359`（报错重检索路径）带了 gameName 能保存——证明是遗漏。
- 修复：消息补 `gameName` 字段（一行）。

### P1-3 RESET_SETTINGS 响应结构不匹配 + 重置可被旧 DOM 值覆盖
- 位置：`background/handlers.js:144-147`（返回 `{ success: true }`）vs `options/panels/data-manage.js:212-219`（判断 `resp.settings`）
- 两层后果：① UI 恒报"恢复默认设置失败"而实际已重置；② 失败分支不重渲染设置面板，DOM 里还是旧值，用户此后改任意设置项触发 `saveSettings()`（从 DOM 全量收集）→ 旧值整包覆盖刚写入的默认值，重置被静默撤销。
- 同类问题：`DELETE_ADAPTER_RULES` 返回 `{ success: true }` vs `options/panels/rules.js:138` 判断 `resp.ok` → "恢复内置规则"永远无成功反馈（对比 `SAVE_ADAPTER_RULES` 返回 `{ok:true}` 匹配——同类消息两种约定混用）。
- 修复：后台响应补字段或 UI 改判 `success`；重置成功后必须重渲染设置面板。

### P1-4 adapterRules 存储层分裂：用户导入规则在内容侧永不生效
- 位置：`content/adapters/builder.js:19`（读 `chrome.storage.local`）vs `background/core/rules.js:214-220`（写 OPFS `dataStore.writeModule`）
- 后台把规则写进 OPFS，全仓库无任何镜像回 `chrome.storage.local` 的代码（已 grep 验证：`storage.local.set` 仅 5 处，均与本模块无关）。内容脚本只读 storage.local：
  - OPFS 可用（桌面 Chrome 常态）：新导入规则内容侧永远读不到，后台（站内搜索/动态注册/规则面板）却用新规则——两端"生效规则"不一致；
  - pre-OPFS 老用户：迁移把旧数据搬进 OPFS 后不删旧键 → 内容脚本永远用陈旧副本。
- 修复：内容侧改走后台消息（`GET_ADAPTER_RULES` 通道已存在），或后台保存时镜像一份到 storage.local（注意双写一致性）。

### P1-5 inferSiteFromDomain 只认 3/6 内置站，3DM/游侠/游民下载网址缓存全被丢弃
- 位置：`background/storage/history.js:13-19`（硬编码 xdgame/xianyudanji/gamer520）→ `background/handlers/download-sites.js:121-131`
- 内容脚本在 gamersky/3dmgame/ali213 正常收集并发送 `TRACK_DOWNLOAD_SITE_VISIT` / `RECORD_DOWNLOAD_URLS_BATCH`，但 `inferSiteFromDomain('www.gamersky.com')` 返回 `unknown` → 整批数据被 `return {success:false}` 静默丢弃。
- 后果：这三站（及所有自定义站点）的"appId → 下载页地址"缓存永不落盘，Steam 页下载站面板快速路径、跨语言兜底检索在这些站点全部失效。
- 修复：站点映射改从规则（`getAllRules` 的 domains/key）动态推断，不再硬编码。

### P1-6 displayName 未转义直拼 innerHTML（XSS 注入点）
- 位置：`content/detail/detail-page.js:191,196,211`（`siteNames[site.key]` 即规则的 `displayName`，未走 `esc()`）
- 数据链已核实：规则字段 `displayName`（rules.js 白名单允许、仅限长 500、不过滤 HTML）→ 导入规则包/数据备份 → 用户访问 Steam 页即注入。同函数其余字段（gameName/updateDate/version/size/detailUrl）全部转义，唯 name 漏网——确属遗漏。
- 同病：`content/detail/detail-templates.js:74-75` SteamSpy `owners` 字段（steamspy.com API 原样字符串）未转义；同文件其余字段均转义。
- 修复：两处补 `esc()`；可选在规则校验层加 displayName 的 HTML 字符白名单。

### P1-7 URL 索引击穿"报错自愈"闭环，错配永久固化
- 位置：`background/handlers/steam.js:43-55`（URL 命中无校验）+ `:302-323`（报错不清理 URL 索引）+ `background/storage/url-index.js:72-79`（无 TTL）
- `handleSearchSteam` 把 URL→appId 索引作为第一候选，命中直接返回且无 `namesRelated` 校验（对比同文件 `handleGetSteamByAppId` 有校验——不对称）；`handleReportWrongAppId` 只清 Steam 缓存/名称索引/网址桶，不清 URL 索引（函数签名拿不到 pageUrl）。
- 后果：用户点"报错" → 重载页面 → 再次命中同一 URL 索引 → 同样的错误 appId 原样返回；换绑的唯一途径（重新标题搜索成功后 setUrlAppId）因 URL 路径短路永远不会执行。列表页阶段 0（ratings-batch.js:36-46）同样直读该未校验索引。
- 修复：URL 命中也过 namesRelated 校验；报错 handler 接收 sender.tab.url 并清 URL 索引条目。

### P1-8 通知点击依赖纯内存状态，30 秒后必失效
- 位置：`background/freegames/manager.js:16-18,458` + `background/service-worker.js:78-86`
- `lastNotifyGames` 是模块级内存变量。通知存活数分钟～数小时，SW 30s 空闲即被杀；用户点击通知唤醒全新 SW 实例，`getLastNotifyGames()` 返回 `[]`，handler 直接 return。
- 后果：v7.4.0"点击通知打开商店页"在常见场景（发出 30s 后点击）100% 失效。
- 修复：通知内容持久化（`chrome.storage.session` 或随 freeGames 模块落盘），onClicked 时读取。

## 三、P2 中危问题（21 个）

### 数据安全与一致性（background）
1. **api-monitor 的 HTTP status 从未传入**（api-monitor.js:25,45；6 个调用点只传布尔）→ `limited` 恒 0（死代码）；Steam 429 若带 JSON 体被记为成功，`failRate/anomaly` 失真——而 ratings-batch 正是用 anomaly 决定降速的。限流感知（模块存在的唯一目的）在最需要时失效。
2. **flush 先清 dirty 再写盘**（steam-cache.js:253-260、registry.js:129-135、name-index.js:111-115）→ 写失败后 dirty 已是 false，数据静默丢失且永不重试（对照 logger.js:75-78 失败回滚才是正确写法）。
3. **OPFS 写失败降级 storage.local 但读端优先 OPFS**（data-store.js:176-200 读 vs 227-243 写）→ 瞬时写失败后旧 OPFS 文件仍在，读取永远返回旧数据，降级写入成不可见僵尸副本，两后端脑裂。
4. **removeModule 不 await init、不进写队列**（data-store.js:278-288）→ "清空缓存"可能与在途写竞态：remove 先执行，随后已入队的 writeModule 重建文件写回旧数据，清空被撤销。
5. **handleCleanExpiredCache 绕过内存直读磁盘**（cache-manager.js:50-64）→ 清理丢弃 2s 防抖窗口内未落盘的脏数据；应先 `flushAllCaches()` 再清理。
6. **updateGameProfile / history 无锁读-改-写**（behavior.js:87-120、history.js:28-56）→ 并发 TRACK_EVENT 丢计数（代码库 download-urls.js:13-27 有 `withStoreLock` 先例，此处遗漏）。
7. **flushLogBuffer 并发竞态丢日志**（logger.js:44-79）→ 定时 flush 与显式 flush 重叠时先写者的批次被覆盖丢弃。
8. **initStorage 与 restoreLatestIfFresh 并发竞态**（service-worker.js:55-57 + settings.js:44-51 + backups.js:154-171）→ v9.6.0 新特性：若 SW 在恢复链路中途被杀，下次启动读到已存在的 DEFAULT_SETTINGS 判定跳过，自动恢复永久失效。应串行化（先 restore 判定，再写默认值）。
9. **refreshFreeGames 无并发防护**（manager.js:294-324；启动/alarm/UI 三处触发）→ 并发整体覆盖写，用户 claimFreeGame 标志可被丢失。
10. **ITAD 二次校验恒失败**（manager.js:329-348 + manifest host_permissions 缺 `api.isthereanydeal.com`）→ CORS 拦截恒走 catch，每次通知都打"ITAD校验失败"误导性 warn。v6.3.3 特性实际不可用。
11. **deepMergeSettings 的 null 绕过**（settings.js:35；`typeof null === 'object'`）→ 存储中嵌套 null 覆盖对象型默认值入库，engine.js:188 对 null 抛错且循环内无 per-game try/catch，GET_RECOMMENDATIONS 整批失败。
12. **批量好评率 keepAlive 不可靠**（ratings-batch.js:85-87,190-192）→ Chrome 110+ SW 存活满 5 分钟后扩展 API 调用不再重置空闲计时器；60 游戏 + anomaly 30s 暂停易超限 → 最多 5 批未 flush 丢失、done 推送不发。

### 内容侧功能缺陷
13. **getAdapter 用"key 当域名段"匹配**（builder.js:288-305，`domain.split('.').includes(key)`）→ 内置站能用纯属 key 恰等于域名段；自定义规则适配器永远选不中回退 `_default`（同文件 :37 与 list-page.js:312 都正确用 domains 匹配——不一致证实缺陷）。与 P1-4 叠加，自定义站点功能双重失效。
14. **适配器对象无 key 属性 → v9.3.0 站点失效告警是死代码**（builder.js:97-128 无 key vs list-page.js:110 判 `adapter.key`）→ SITE_ADAPTER_ALERT 从未触发过。
15. **window.open 拦截在隔离世界无效**（download-tracking.js:47-53）→ manifest 未声明 MAIN world，覆盖的只是隔离世界全局，站点 JS 的 window.open 完全不被拦截；"网盘新窗口打开"追踪路径对真实页面行为是死的。
16. **gamer520/xianyudanji 的 detailUrlPatterns 过宽**（`'/[^/]+/?$'` 匹配所有单段路径）→ /about、/login、导航/分类链接全被当"详情页"，错误徽章/错误过滤。
17. **migrate.js 迁移链缺 from 校验 + 迁移函数返回 undefined 清空模块**（migrate.js:58-62）→ 当前无调用方（框架预留），首个真实迁移接入即成隐患。
18. **showStatus 参数错位**（list-batch.js:231、:113）→ 描述字符串传给了 total 形参，进度详情文案永不显示（fireBatch 内 :84-89 调用是对的——笔误）。
19. **限免页截止日期非法时原文回填 innerHTML**（freegames.js:144,212-216）→ 外部 API 字段未转义（扩展页 CSP 挡住脚本执行，HTML 仿冒仍可行；同卡片其余字段全转义）。

### UI 一致性
20. **缓存表 colspan 不一致**（cache.js:172,188,206 用 10，:261 用 11，表头实际 11 列）→ 空态行缺一格。
21. **filterRules 输入框 value 只转义双引号**（options.js:177,179）→ `&` 未转义，实体样式关键词显示错乱（非 XSS；同页有现成 escapeAttr 未用）。
