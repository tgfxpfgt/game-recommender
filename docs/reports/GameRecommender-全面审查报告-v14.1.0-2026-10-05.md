### 2.2 更值得警惕的是：新代码正在往盲区里加

补充轮 P0-1 已指出 `options/`、`dashboard/`、`popup/` 等目录**不在覆盖率门禁与全局阈值的统计范围内**
（4492 行 UI 代码完全在覆盖率视野之外）。而 v14.1.0 的新增生产文件恰好又落在这些目录：

| 新增文件 | 行数 | 目录 | 在覆盖率门禁内？ | 有测试？ |
|---|---:|---|---|---|
| `options/panels/reset-defaults.js` | 196 | options | ❌ 逃逸 | ❌ **零测试** |
| `background/core/tab-game.js` | 57 | background | ✅ 在门禁内 | ✅ `test-tab-game.mjs` |
| `options/panels/settings.js`（+66） | — | options | ❌ 逃逸 | ❌ |
| `dashboard/dash-insights.js`（+33） | — | dashboard | ❌ 逃逸 | ❌ |
| `content/list/xdgrid.js`（+94，过滤预设） | — | content | ✅ 在门禁内 | ❌ |
| `content/detail/detail-templates.js`（+167） | — | content | ✅ 在门禁内 | ❌ |

**这不是巧合，而是结构性的**：UI 层永远是功能交付的主战场，而 UI 层恰好没有任何量化护栏。
`reset-defaults.js` 是最典型的一例——196 行新代码，零测试，且**根本不会被任何门禁发现它没有测试**。

### 2.3 一个反直觉的推论

项目目前的门禁读数是"全绿"的：lint 0/0、tsc 零错误、858/859。
但拆开看——

- 那 1 个失败是**环境假阳性**（不是真缺陷，但也说明哨兵测试本身不可靠）
- 4492 行 UI 代码**不在覆盖率分母里**
- 覆盖率门禁对新增文件的要求，73% 的新增文件**因目录白名单而豁免**
- 棘轮文件记录了数字**但没有任何程序读它**，所以"只降不升"只是文档承诺

也就是说：**绿灯的亮度，有一部分来自盲区，而不是来自代码真的没问题。**
这正是补充轮报告标题"护栏假象"的含义，本次复核确认该判断成立且**未被处理**。

## 3. 本次新增发现

### 🟠 P1-1：`reset-defaults.js`（196 行）零测试，且无任何门禁会发现这一点

**位置：** `options/panels/reset-defaults.js`（v14.1.0 新增）

该文件实现了"设置项 hover 显示 ↺ 按钮、单击恢复该键默认值"，包含
`ensureDefaults`（异步取 `GET_DEFAULT_SETTINGS`）、`getPath`（嵌套路径读取）、
`resetOne`（写回 + 重渲染）、`makeButton`（DOM 构造）、`bindResetDefaults`（MutationObserver + click 委托）
等 5 个函数，涉及**嵌套路径解析**与**异步写入**两类易错逻辑。

**风险：** 嵌套 `getPath` / `resetOne` 这类路径处理是典型边界用例温床
（路径不存在、数组索引、深层嵌套组如 `badgeVisibility.*`），零测试意味着回归只能靠手感。
且因目录白名单，`coverage:gate` 不会拦截它——**它可以在"零测试"状态下无限期存活**。

**建议：** 至少补 `getPath` / `resetOne` 的单元用例（嵌套组、不存在路径、默认值等同）。
若暂时不补，也应把 `options/` 纳入 `COVERED_DIRS`，让门禁能看见它。

### 🟠 P1-2：`freegames/manager.js` 逆势增长至 741 行，拆分持续欠账

v14.1.0 又向其 +27 行（收藏价格相关）。它是全项目最大文件，且混装三个职责域
（限免抓取 / ITAD 价格 / 通知角标）。上一轮已列为 P2-1，本轮**从 716 增至 741**。

同时 `content/list/xdgrid.js` 因过滤预设功能从 505 增至 **603 行**，成为新的第三大文件。

**建议：** 在下一轮迭代中把 `freegames/manager.js` 三域拆分与 `xdgrid.js` 预设逻辑外移一并处理；
否则这两个文件会在每次"顺手加一点"中持续膨胀，抵消 v14 拆分浪潮的成果。

### 🟡 P2-1：`tab-game.js` 的容量淘汰逻辑值得肯定，但缺少边界用例

公平地说，这个新模块写得**不错**：`noteTabGame` 做了 tabId 整数校验、
各字段长度截断（appId 12 / name 200 / image 500）、`MAX_TAB_ENTRIES = 24`
按时间淘汰最旧防无界增长。这比很多存量代码严谨。

但测试 4 例是否覆盖"容量达上限时的淘汰正确性"与"`at` 相同时的排序稳定性"未见体现。
建议在 `test-tab-game.mjs` 补两个用例：上限淘汰顺序、`at` 全等时的行为。

### 🟡 P2-2：`BUILTIN_DOMAINS` 已导出但零消费，单源化停在"导出"这一步

`background/core/site-scripts.js:22` 已 `export const BUILTIN_DOMAINS`，
但全仓库测试中零引用——`test-integrity` 里仍是硬编码的 7 域名正则。
导出了却没人用，等于单源化做了一半；下次加站点仍可能只改一处。

**建议：** 让 `test-integrity` 的域名三方一致性检查改为 import `BUILTIN_DOMAINS`，
正则硬编码随之删除（成本约 3 行，可彻底关闭这个漂移点）。

## 4. 正面确认（本次独立复核通过）

这一节记录审查通过项，它们是项目真正的资产，也是不该退化的基线。

- **功能交付质量高**：v14.0.0 一次性修掉 7 个真 bug，其中
  `TRACK_EVENT_BATCH` 无 handler 且契约默认拒绝（攒批事件整批丢弃）是**真实用户可见缺陷**，
  说明审查确实挖到了东西并得到了修复。
- **新模块 `tab-game.js` 工程质量好**：输入校验、长度截断、容量上限、按时间淘汰俱备（57 行）。
- **lint 零警告是真零**：`--max-warnings 0` 实测 EXIT=0，非靠 disable 堆砌。
- **分层矩阵零违规**：`data/` → `background/`、`shared/` → `background|content`、
  `content/` → `background/` 全部无越界（v14.0.0 为错误归一开放 shared 层，属有意调整）。
- **存储注册表 / 内容模块清单**：两张核心单源表仍零漂移。
- **测试增长健康**：859 用例 / 37 套件，且 v14 新增 3 个测试文件，方向正确。

## 5. 建议的修复顺序（按"每次写代码都会再踩"的频率排序）

| # | 事项 | 级别 | 成本 | 为什么优先 |
|---|---|---|---|---|
| 1 | `COVERED_DIRS` 与 `vitest include` 纳入 UI 目录（`options/dashboard/popup/freegames/hub/welcome`） | P0 | 低（2 行） | 一次性关闭 4492 行代码的盲区，此后所有 UI 新代码自动进护栏 |
| 2 | 修 `test-integrity` 语法检查假阳性（区分 `e.status === null`） | P1 | 低（~10 行） | 消除 128/128 误报炸弹，让哨兵测试恢复可信 |
| 3 | `lint-baseline.json` 加程序读取（或明确降级为文档，不再称"棘轮"） | P0 | 低 | 现状是"声称有棘轮，实际没有"，比没有更危险 |
| 4 | 补 XSS 转义静态扫描（先落基线再清零） | P1 | 中 | 唯一"靠自觉"的铁律，110 处 innerHTML 无兜底 |
| 5 | `reset-defaults.js` 补嵌套路径用例 | P1 | 低 | 196 行新代码零测试，且门禁看不见它 |
| 6 | `gate.mjs` 并入 `coverage-gate` / `release-smoke` | P1 | 低 | 本地全绿 ≠ CI 绿灯 |
| 7 | `SITE_SCRIPT_FILES` 真单源化（manifest 由脚本生成或加一致性测试） | P0 | 中 | 铁律 #13 声称它是单源，实际两份手工副本 |
| 8 | `freegames/manager.js` 三域拆分 + `xdgrid.js` 预设外移 | P2 | 中 | 阻止 741 / 603 继续膨胀 |

**关于优先级的说明**：上表刻意把"低成本、高频收益"的门禁修复排在功能拆分之前。
当前项目不缺功能交付能力——两个版本 13 项功能证明了这一点；
缺的是让既有质量不再滑坡的自动化约束。**每修一项门禁，等于给未来所有代码加了保险。**
