### 🔴 P0-2：`coverage:gate` 当前崩溃退出（exit 1），且存在"假 0%"误判通道

实测 `node scripts/coverage-gate.mjs`：
```
📁 新增文件 1 个，运行覆盖率门禁（行覆盖 ≥ 50%...
   - background/core/tab-game.js
Error: Command failed: npx vitest run --coverage ...
  ❌ background\core\tab-game.js      ← 这是 spawn 报错文本，不是覆盖率数字
REAL_GATE_EXIT=1
```

**三层问题叠加**：

**(a) 前轮 P0 未修导致**：`test-integrity.mjs:199-210` 的 `catch {}` 不区分"语法错"与"spawn 失败"，本环境 `cmd.exe EBUSY` → **128/128 全盘假阳性**（前轮 125 → 现 128）。vitest 因该失败非零退出。

**(b) 门禁脚本未捕获退出码**：`scripts/coverage-gate.mjs:61` 的 `run()` 用 `execSync` 但不捕获非零退出，异常直接冒泡 → 门禁不是"失败"而是"崩溃"，覆盖率表格根本不产出。

**(c) 表格解析可静默假放行**（最危险）：`coverage-gate.mjs:67-75` 用 `tableRe` 解析文本表格，**找不到匹配行就 `if (!m) continue`**。若 vitest 输出因任何原因不含该文件行 → `failed` 数组为空 → 打印"✅ 覆盖率门禁通过"。

**(c) 当前因 (a) 导致 vitest 崩溃才没走到这里，属侥幸。** 一旦 spawn 问题被修好，若输出格式变化就会命中这条假放行通道。

**附带**：`coverage-gate.mjs:72` 用 `file.endsWith(path.basename(f))` 匹配，basename 比对在同名文件时会误匹配（`options/panels/settings.js` 与 `background/handlers/settings.js` 同名）。当前 v14.x 新增文件 basename 唯一未触发，但一旦同时进入 `newFiles` 就会串。

**修复**：
1. `test-integrity.mjs` 区分 `e.status === null`（spawn 失败 ≠ 语法错），并加哨兵自检——先跑一个已知合法文件，失败则整体报"spawn 不可用，门禁未执行"（**不允许静默通过**）
2. `coverage-gate.mjs:61` 捕获退出码并友好报错
3. `coverage-gate.mjs:67-75` 改为"找不到匹配行即失败"，杜绝假放行
4. `:72` 改用完整相对路径比对
