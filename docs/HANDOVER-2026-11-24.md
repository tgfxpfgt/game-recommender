## 2. 日常循环（最小闭环）

```
改码（先查 playbooks）→ npm run test:changed -- <改动文件> → npm run gate:fast
→ npm run bump patch|minor "标题" "要点..." → commit（CC 1.0.0）→ push（pre-push 钩子自动门禁）
```

- 单文件小改可只跑受影响套件（用户指令 2026-11-10：测试最小化）。
- 完整发版触发线：大版本 / 5 次 minor / 单批 >1000 行 / 累计 >3000 行——见 AGENTS 发布流程。
- **提交前 pre-commit 会跑 prettier 全量校验**：新写的文件先用 `npx prettier --write` 格式化，
  否则钩子逐个文件拒收（曾一单一单被弹回 3 次）。
- push 时 pre-push 跑 lint+typecheck+受影响测试；失败会拒推，按输出修复后重推。

## 5. 已知坑（历史实证，勿再踩）

- **并行会话**：多 AI 窗口并行写本仓库是常态。教训：未提交改动可能被对方 `git stash`「暂存让路」
  （stash 名会写明），恢复用 `git stash pop`；提交前 `git status` 复核自己的文件清单，
  commit 只 add 自己批次的文件。
- **echo $[] 误报**：`cmd | tail; echo $?` 取的是 tail 的退出码——判断成败用 `${PIPESTATUS[0]}`。
- **heredoc/python 内嵌代码**：含反引号/嵌套引号的补丁一律用 Edit 工具 + 写后 grep 回读；
  sed 插入 `\n` 会被吃成真换行（曾把测试文件改到语法错误）。
- **MV3 铁律 2**：SW 禁动态 import()——AGENTS 有专条，历史复证两次。
- **徽章组标记契约（铁律 12）**：`gr-rating-badge` 是组标记，组外徽章必须 `base:'gr-badge'`。
- **双管线一致性（铁律 18）**：列表/详情共语义逻辑走单源（match-confidence / mcColorFor /
  specificPlatformTag / steamMissingResult），新增共享语义先入单源再接两侧。
